## 车体、场地与控制链路的关系 {#system-hardware-relationship}

```text
车顶 AprilTag ── 俯拍相机 ── USB ── Server 电脑 ── Ethernet ── 路由器/AP
      │                                                              │
      └─ 车体、ESP32、编码器电机、电池 ───── Wi-Fi / UDP ──────────────┘
```

1. **车体层**：两台带编码器的减速电机负责驱动，34 mm 轮形成差速底盘，CY-12B 只负责支撑；电池和电源转接线必须先确认极性、额定电流和固定方式。
2. **控制层**：车端控制板运行 ESP32 固件，读取编码器、执行轮速闭环并通过 Wi-Fi 与 Server 通信。任何替代板都需要先完成板卡型号、引脚、电源和驱动芯片核对。
3. **视觉层**：固定相机识别车顶标签和场地固定标签，视觉服务把像素转换为场地坐标；标签的黑框尺寸、安装高度和朝向必须以实物测量值写入配置。
4. **场地层**：3 × 3 m 是有效运动区域，方管和连接件只构成相机支架或边界辅助结构，不应占用车体运动空间。Server 和路由器放在场外，减少碰撞、线缆和无线遮挡。

当前代码按差速车的轮轴中点作为控制参考点。车顶标签中心相对轮轴的前向偏移、车体外廓和电机减速比都不能从商品标题推断，必须在首车装好后重新测量。

## 设计思路与复用原则 {#design-principles}

1. **先定义接口，再选同类器件**：电机、电池、相机和连接器可以替换，但必须保持电压、电流、针序、安装孔位和数据语义一致。商品名不是接口定义。
2. **把假设写成可测量参数**：轮径、轮距、编码器每圈计数、标签黑框尺寸、标签高度、控制点偏移和相机内外参都进入配置或验收记录；未测量的值只能标为名义值。
3. **车体和场地分开验收**：先完成一辆车的电气、机械和轮速闭环，再固定相机和标定场地，最后才扩展到多车。这样可以区分电机、定位和网络问题。
4. **公共设备集中化**：相机、Server 和路由器属于场地公共设备；车端只承担实时控制和反馈，避免为每辆车重复配置电脑或视觉模块。
5. **公开文档只保留可复用信息**：价格仅帮助估算成本，图纸、接口、边界条件和验证步骤才是参考价值的主体。供应商、物流状态和一次性优惠不应成为设计依赖。

动力数据属于设计候选的名义核算：1:20 电机配 34 mm 轮时，供应商额定点 500 rpm 对应约 0.89 m/s，空载约 1.96 m/s；表中 1:100 的名义额定点约 0.23 m/s。当前验证样件是 1:100，因此应按实物铭牌和测量结果重新设置测试速度与控制限制。载荷、低电压、原地转向和温升决定实际可用速度，不能用空载转速设围堵速度上限。

差速/unicycle 的参考点是驱动轴中点。标签居中时在轮轴前方约 **30.5 mm**，需补偿标签偏移；车体前缘在轮轴前约 78.1 mm，车体包络也需正确偏置。控制与视觉默认值仍为 V11，装车后填写实测黑框尺寸、高度、偏移、轮径、轮距和编码器计数。

## 为什么是这套布局 {#why-this-layout}

两驱动轮与一个低阻支撑点对应差速模型；电池低位放置，标签板提供稳定几何参考。设计尽量使用通用紧固件和两件式打印结构，降低首次装配的复杂度。

车体稳定、球轮阻力、支架同轴度和编码器反馈，会直接影响低速控制。名义几何正确不能证明摩擦、回差、打印强度或停止行为合格。
