# 路线图

路线图以交付条件组织，不给尚未验证的能力承诺日期。先确保公共平台可理解、可运行，再逐步承担研究环境职责。

## 现在 · 开发预览

- 提供控制服务、Web 控制台、独立视觉、固件与 V11 参考设计。
- 提供清楚的操作、接口、设计取舍和验证边界。
- 运行跨端协议测试、软件检查与四车固件构建。
- 通过 GitHub Pages 持续发布文档。
- 提供可独立安装的同步 Python SDK，覆盖类型化状态、联合动作、控制会话与退出释放。

当前状态见[能力与验证](../guide/status)。

## 下一步 · 可复现参考平台

验收条件是另一位使用者能按公开材料搭起同一参考组合，并得到可解释的运行结果。

- 首车尺寸、接线、电机与相机标定的实测记录。
- 一车、双车、四车的基本运动与故障测试。
- 通过外部实验验证 Python SDK 的生命周期、超时与错误行为，形成稳定兼容承诺。
- 一个完整实车参考例子与日志解析说明。
- 版本化的软硬件兼容清单。

## 随研究需求推进 · 实验环境

- 固定步长、可配置扰动的轻量差速仿真。
- 少量标准任务、基线、回合与终止管理。
- 原始观测/动作/执行关联、评测与回放。
- 按研究规则隔离观测和通信。
- 存在实际用户需求后，增加 PettingZoo、ROS 2 等可选适配。

论文中的方法、训练配置和权重在独立实验仓保存，并固定依赖 ACField 提交或版本。经过多项实验证明通用的能力再进入平台。

## 如何确定优先级

欢迎带着可复现的搭建问题、测量记录或明确研究流程提出 issue。影响复现和失效行为的问题优先；新抽象应由至少一个具体使用场景支撑。可独立发布、已有外部用户和维护者的模块，才重新评估是否拆仓。
