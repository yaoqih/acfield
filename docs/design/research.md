# 研究边界与实验有效性

ACField 是真实系统的公共基础层。能发送多车动作，意味着具备研究接入点；形成可比较的多智能体实验，还需要明确任务与证据链。

## 当前适合探索的方向 {#research-directions-to-explore}

低速编队、追逃、协同到达、覆盖与任务分配可以作为后续任务方向。预训练策略也可以通过速度接口部署，但必须适配差速运动、实际频率、延迟与停车规则。具体效果以测量为准。

场外相机当前只提供公共定位。原始图像共享、BEV 融合、协同 SLAM 或车载自主感知需要额外设备或数据流，不能用四车运动演示替代这些能力。

## 集中基础设施与分散策略 {#central-infrastructure-and-decentralized-policies}

多个 agent 可以在同一电脑上运行，也可以读取由适配层生成的局部观测。策略是否分散，取决于实际可获得的信息与消息规则，而不是进程是否分开。

当前 `/api/state` 是全局平台状态，尚未实现观测隔离。研究受限通信时，需要先构建观测与消息适配层，防止各 agent 通过公共状态接口获取规则外的信息。评估与停车保护可保留全局状态，但应明确与策略隔离。

逻辑消息延迟、丢失与字节预算模拟属于算法通信条件。电脑到 ESP32 的执行 UDP 流量是另一条链路。两者需要分别统计，逻辑通信实验不能直接宣称真实 V2V 无线协议性能。

## 动作与时序契约 {#action-and-timing-contract}

参考接口使用 `v` 与 `omega`，速度需满足差速执行约束：

```text
v_left  = v − omega × wheel_track / 2
v_right = v + omega × wheel_track / 2
```

二维平面速度、目标点和轨迹需要显式跟踪器。记录推理时间、观测数据龄和动作有效期，拒绝过时结果；不要用持续续发旧命令掩盖策略阻塞。

## 报告保护干预 {#report-protective-intervention}

至少区分策略请求、限幅/拒绝后的动作、车端确认与真实运动。方法依靠保护层频繁制止碰撞时，应分别报告任务效果和保护贡献。

建议记录成功、失败和中止三个结果类别。设备故障、定位失效或日志丢失造成的中止，需要预先约定统计规则；不能只删除失败运行。

## 一个可复现任务的最小清单 {#minimum-specification-for-a-reproducible-task}

| 要素 | 应说明的内容 |
| --- | --- |
| 任务 | 目标、参与车、结束判据、最大时长 |
| 观测 | 坐标、局部/全局范围、数据龄、噪声 |
| 动作 | 单位、频率、限制、超时、跟踪器 |
| 初始条件 | 仿真种子或实车摆位与允许误差 |
| 版本 | 平台提交、固件、模型权重、标定配置 |
| 指标 | 成功率、时间/误差、干预、通信与推理开销 |
| 结果 | 所有运行清单、无效/中止理由、统计方法 |

当前主控日志已覆盖工程链路的一部分；回合 ID、agent 观测、消息与任务评估需要实验层补充。实车不能像固定种子的仿真一样精确复位，应记录初始误差和环境变化，并用重复试验估计波动。
