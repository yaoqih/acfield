# 系统架构

ACField 当前采用“一台电脑管理公共基础设施，每台车执行本地闭环”的结构。参考策略约以 10 Hz 提交速度，固件独立运动任务以 50 Hz 检查命令与更新轮速闭环。这些是实现配置，端到端性能需要测量。

## 数据与控制路径 {#data-and-control-paths}

```text
固定相机
  │ 图像
  ▼
apriltag_live.py ── 世界坐标、来源、帧龄 ──┐
                                         ▼
策略脚本 ── HTTP 联合速度 ──► robot_server ◄── Web 控制台
                              │    │
                     JSONL ◄──┘    │ Wi-Fi / UDP
                                   ▼
                             ESP32 / 每台车
                      TTL、轮速闭环、故障锁存
                                   │
                             双编码器电机
                                   └── 遥测回到主控
```

## 模块职责 {#module-responsibilities}

| 模块 | 负责 | 不在该层隐式完成的工作 |
| --- | --- | --- |
| 定位服务 | 检测、外参、标签高度修正、来源与数据龄 | 策略规划、设备身份控制 |
| 控制服务 | 状态、控制权、联合校验、保护、通信与记录 | 训练、研究任务定义 |
| Python SDK | 类型化 HTTP 客户端、显式动作、控制会话与条件释放 | 后台续发旧动作、策略与任务定义 |
| 策略脚本 | 观测到动作的映射、算法自身状态 | 绕过底层解锁与时效检查 |
| 车端固件 | 报文校验、轮速执行、TTL 与设备故障 | 场地全局定位、路径规划 |
| Web 控制台 | 手动操作、配置、调试状态 | 可靠替代后端超时机制 |

## 一个状态所有者 {#one-owner-of-state}

FastAPI 单进程维护车辆、控制权和指令状态，SQLite 保存配置，实时轨迹保存在有界内存结构中，JSONL 通过有界队列写入。前端由同一服务托管，运行阶段不需要 CDN。

必须使用单 worker。增加 worker 会复制内存状态并争用 UDP 端口，不能直接带来控制服务的扩展。CPU 密集策略应在外部进程运行，通过接口提交有期限的结果。

## 多车动作的原子边界 {#atomicity-of-joint-actions}

`POST /api/commands` 基于同一批候选动作统一校验，失败时不会部分下发这批新的运动动作。请求涉及且属于该控制源的车辆会被停车锁定。

这个边界位于主控校验层。UDP 到达、设备调度和电机启动仍存在偏差，一次联合请求不代表四车硬件同步。需要严格执行同步的实验必须增加时序协议与测量证据。

## 坐标与控制点 {#coordinates-and-control-point}

世界位置单位为米，角度为弧度，逆时针为正；车体 x 向前，y 向左。差速控制点使用驱动轴中点。标签偏移表示“控制点到标签中心”的车体系向量：

```text
车体朝向 = 视觉世界朝向 + heading_offset
控制点 = 标签中心 − R(车体朝向) × 标签偏移
```

标签板几何中心与驱动轴中点不同：95 mm 亚克力候选的居中标签名义在轮轴前方 30.5 mm，旧 V11 约 16 mm。实际朝向与偏移必须装配后核验。车体轮廓偏移和标签偏移是不同参数，不能只改标签尺寸而沿用旧偏移。

## 工程模块与仓库 {#engineering-modules-and-repositories}

当前保留已联调的软件路径：`robot_server/`、`esp32_software/firmware/`、根目录视觉脚本与 `web/`。路径稳定有助于保留跨端测试。后续可以在不改变外部接口的前提下整理包结构；模块化不要求现在就拆分仓库。

`sdk/python/` 单独构建和安装为 `acfield` 包，不导入后端实现。服务器、SDK 与文档仍在同仓评审；算法可以在自己的虚拟环境或另一台实验电脑中安装 SDK，并通过 HTTP 连接主控。详见 [Python SDK](../guide/python-sdk)。
