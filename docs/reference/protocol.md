# 设备协议与时序

当前设备使用 UDP JSON 协议 `version=1` 的显式解锁修订。服务端与本仓固件应一起使用；历史 v1 报文不一定具备当前必需字段，不能只依据数字 1 判断兼容。

## 身份与会话

`robot_id` 是持久车号，`boot_id` 每次设备启动改变，遥测与命令各有递增序号。主控用 `session` 标识控制会话，设备只接受符合当前启动、会话及序号规则的指令。

设备约以 20 Hz 向主控 UDP 9999 发送遥测，主控回发来源端点。默认四车身份为 `car-01` 到 `car-04`，不能把四块板全部烧成同一个身份。

## 状态转换

```text
启动 / 断联
    ↓
unbound ── 新鲜遥测回显 + stop ──► disarmed
                                     │
                               显式 arm + 确认
                                     ↓
                                   armed
                                     │
                       stop / TTL / 链路或设备故障
                                     ↓
                              disarmed / fault
```

故障锁存后需排除原因并重启设备。重连只恢复通信条件，不恢复运动。

## 命令示例

```json
{
  "version": 1,
  "type": "command",
  "action": "drive",
  "session": "server-session",
  "robot_id": "car-01",
  "boot_id": "per-boot-id",
  "telemetry_seq": 42,
  "seq": 8,
  "v": 0.05,
  "omega": 0.0,
  "ttl_ms": 300,
  "stop": false
}
```

- `stop`：双零速度、`stop=true`，停车并取消解锁，也用于绑定新会话。
- `arm`：双零速度、`stop=true`；已绑定、无故障且回显新鲜才可显式解锁。
- `drive`：已解锁后执行速度；运动必须回显当前启动最近发送的遥测。双零且 `stop=true` 只停车，不重新解锁。

绑定新会话须回显 200 ms 内且晚于上次绑定界限的遥测；旧会话历史报文不能重新绑定。重复命令不会刷新运动 TTL。

## 遥测

包含身份、启动 ID、序号、`device_state`、固件版本、`ack_session/ack_seq`、电压、编码计数、左右轮速、速度限制、故障与停车原因。未得到可信测量的值填 `null` 或省略。

协议解析与状态机源文件位于 `esp32_software/firmware/include/command_wire.h` 和 `protocol.h`。跨端测试会编译实际解析器，让服务端生成的报文进入真实固件逻辑。

## 当前时序配置

| 环节 | 配置值 | 含义 |
| --- | --- | --- |
| 车端运动任务 | 50 Hz | 检查 TTL 与更新轮速控制 |
| 车端遥测 | 20 Hz | 设备状态与反馈 |
| 主控状态推送 | 10 Hz | 最新快照 |
| 策略建议更新 | 约 10 Hz | 需要结合推理与链路实测 |
| 心跳期限 | 1 s | 过期锁定 |
| 定位期限 | 200 ms | 过期失效 |
| 默认动作期限 | 300 ms | 可配 100–500 ms |
| 绑定/解锁重试 | 150 ms | 维持相应序号重试 |

这些是软件门限和调度目标，不是已测量的无线延迟或物理停止时间。测量端到端延迟时应明确时钟基准，不能直接相减不同设备未同步的时间戳。
