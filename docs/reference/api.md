# HTTP 与 WebSocket

控制服务默认位于 `http://127.0.0.1:8000`。运行时 OpenAPI 在 `/docs`；本页说明主要语义。

## 接口清单

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/health` | 模式、关键任务、就绪、记录健康 |
| `GET /api/state` | 当前场地、车辆、相机与事件快照 |
| `GET /api/config` | 当前持久配置 |
| `PUT /api/config` | 校验并保存；要求全部车辆锁定 |
| `POST /api/robots/{id}/arm` | `{"enabled":true}` 解锁；`false` 锁定 |
| `POST /api/robots/{id}/command` | 单车速度命令 |
| `POST /api/commands` | 统一校验一批多车速度 |
| `POST /api/stop` | 全局停车并锁定 |
| `POST /api/reset-stop` | 释放全局停止，不解锁车辆 |
| `GET /api/camera/stream` | 转发配置的视觉 MJPEG |
| `WS /ws` | 约每 100 ms 最新状态，无历史推送队列 |

## 动作格式与限制

```json
{
  "car-01": {"v": 0.05, "omega": 0.0, "ttl_ms": 300},
  "car-02": {"v": 0.05, "omega": 0.0, "ttl_ms": 300}
}
```

上例用于 `/api/commands`。单车端点直接接收内部的速度对象。模式中 `v` 允许 −1 到 1、`omega` 允许 −6 到 6，实际命令还按车辆配置与设备限制取更小值；这些 schema 上限不是推荐实车速度。TTL 允许 100–500 ms。

解锁和非零动作必须带 `X-Control-ID`。保持与解锁时一致的 ID。零速度请求允许停车，但不会自动解除锁定或全局停止。

## 响应与状态

非法输入返回 422；车辆不存在返回 404；控制权、定位、保护或解锁条件不满足通常返回 409。联合校验失败不会下发本批新的部分运动动作，并锁定请求中属于该控制源的车辆。

`armed` 只在设备确认相应状态后成立。设备 ACK 证明协议状态确认，物理运动需要结合轮速与视觉反馈检查。

`ready` 针对全部配置车辆，而不是某个实验参与子集。主控支持 1–16 台配置记录，已提供四台参考固件构建环境；更大规模需单独验证。

## 状态数据

位置与朝向为 `x/y/theta`，身份在 `robots[].config.id`。还应检查在线、定位、解锁、故障、命令确认、轮速、电压与停车原因。未知测量使用 `null`，不可作为零值解释。

HTTP 读取和 WebSocket 都提供最新快照，没有保证每个历史状态都会被客户端看到。逐次实验记录应使用日志，并补充实验层的观测/动作关联。
