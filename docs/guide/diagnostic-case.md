# 案例：遥测空档与断续运动

2026-11-12 的排查记录涉及多个历史构建。本文保留证据与推理，当前操作入口见[故障排查](./troubleshooting)。

## 现象与证据 {#evidence}

| 时间与构建 | 观察到什么 | 当时能判断什么 |
| --- | --- | --- |
| 15:50:51、15:51:00、15:51:15 | 主控约每 25 ms 发包，有效遥测空档约 600–770 ms，ACK 停滞，设备报 `command_timeout` | 运动回显期限 200 ms，持续发送也可能被车端拒绝 |
| 16:05–16:09 | 8 次 1046–1129 ms 空档，boot 未变，无故障，`motion_echo_rejections=0` | 旧 1 s 主控心跳先触发离线停车 |
| 16:08:19.723–16:08:20.771 | 左计数变化 2483，按当时标定约 4.22 m/s | 原始计数与旧测速校验范围冲突 |
| 16:09:13.122–16:09:14.177 | 左计数变化 33524，约 56.6 m/s | 需检查线材与计数，估算速度不可直接当实际车速 |
| 16:10:53 后的新运行 | 581/698 ms 空档后仍为 `armed/driving`，16:13:16 按 120 s 截止停车 | 较宽心跳与主控续发已生效，发生在测速校验修复前 |

旧主控将轮速与线速度限制在 ±3 m/s、角速度在 ±30 rad/s，越界整包被丢弃，连带丢失心跳、ACK 与原始计数。已接受样本的最大轮速恰为量化后的 2.848 m/s，与校验丢包吻合。旧日志缺少拒收事件，无法逐包排除叠加的网络丢包，也无法还原通用“控制源已释放”对应的页面事件。

## 修复与当前检查 {#fixes}

诊断 0.2.4 将运动回显窗口放宽至 1500 ms，绑定与解锁保持 200 ms，并增加 `motion_echo_rejections`。主控普通与诊断心跳统一为 3 s，持续诊断截止从页面 30 s 改为主控 120 s，运动 TTL 保持 500 ms。

主控保留有限的原始测速值，拒绝 NaN/Infinity，并新增 `udp_received`、`udp_rejected`、`udp_rejections` 与逐次拒收记录。校验修复更新主控即可生效。当前诊断版本与刷回普通固件的方法见[诊断流程](./troubleshooting#encoder-diagnostics)。

再次遇到空档时，先比较拒收计数、设备回显拒收计数与 ACK，再看 Wi-Fi、供电和线材。更宽心跳只能容忍返回链路的短暂空档，运动期限仍独立生效。

## 反馈异常与抖动 {#feedback-oscillation}

0.2.6 曾在约 0.17 m/s 的目标下记录约 5.98 m/s 左轮估算反馈。PI 比例项可能因此将正向输出压到零，反馈回落后再升高，形成反复加速。0.2.7/0.2.8 的开环构建用于隔离反馈路径，当前普通固件已恢复闭环。

复测时一起保留目标、原始计数、轮速、PWM 与负载电压。反馈突跳先查计数，输出稳定仍抖动时继续查起转占空比、供电、驱动和机械阻力。
