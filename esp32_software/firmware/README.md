# General Driver for Robots 固件 0.2.9

适用 SKU23730 / ESP32-WROOM-32UE + TB6612FNG，与 `robot_server` 配套。主控是ESP32，无需STM32或额外串口桥。供应商示例不在本仓分发；平台参考见 [ACField 文档](https://yaoqih.github.io/acfield/hardware/bringup)。

## IMU 诊断遥测（0.2.9）

新增板载 QMI8658C 六轴原始采样，必须先更新服务端以接受 `imu` 字段，再烧录车端。与 INA219 共用 SDA32/SCL33，由同一个低优先级传感器任务访问 I2C；电机任务仍独立 100 Hz。芯片配置为 125 Hz、加速度 ±8g、陀螺仪 ±1024°/s；约 100 Hz 读取最新样本，现有 40 Hz 遥测仅发送其中最新一份，不保存全部芯片样本。未接入磁力计，不自动修改方向控制。

`imu` 包含 `sampled_mono_us`（本次读取完成时的车端单调微秒）、`sensor_ticks`（芯片原始 24 位时间戳）、`age_ms`（发送时的读取年龄）、`saturated`、`accel_m_s2` 和 `gyro_rad_s` 三元数组。轴向为**芯片坐标系**，不是已校准车体系；加速度包含重力的影响，静止约 9.81 m/s²。初始化或读取失败时为 `null`；IMU 不可用不改变原有电机保护。服务端 `/api/state` 和运行记录保留这些字段；现有 `acceleration` 仍是视觉计算量。

实车使用前需要检查约 1g 静止读数、持续更新的芯片时间戳、静止陀螺仪偏置，并手动逆时针转车核对正方向。短时相对航向可以由去偏后的陀螺仪积分估计；运动时加速度不能直接当成倾角，六轴也不能提供无漂移的绝对航向或可靠的米级位移。

2026-11-13 已将 0.2.9 烧录到 car-01，实测芯片时间戳持续更新，静止和短时前后运动均收到真实 IMU 遥测。该车静止加速度模长约 9.30 m/s²；陀螺仪 X/Y/Z 零偏约 +15.0/+2.3/−2.1°/s，分析时必须先测零偏。倒退逆时针转动已由用户观察与去偏 IMU 正方向交叉核对；手动转角尚未完成独立比例校准，原始积分角度不能视作已校准真值。当前只用于诊断，没有启用 IMU 航向闭环。

## 配置与构建

1. `cp include/secrets.example.h include/secrets.h`，填写实际Wi-Fi和主控电脑IPv4。凭据文件不会进入版本控制。
2. `include/config.h`采用V10/V11名义轮径34mm、轮距122mm，电机为A12、12V、1:20；额定500rpm对应约0.89m/s，固件线速度及轮速上限均为0.89m/s，角速度上限为3.00rad/s。主控新建车辆默认限速0.50m/s、1.50rad/s，实际还受已保存的车辆配置限制。
3. 校准前先设`motorsEnabled=false`（当前配置为`true`），烧录后查看控制台“左/右编码计数”，手动分别转轮若干整圈，取计数差绝对值/圈数。左右轮`pulsesPerTurn`当前均为60，由旧1:100配置的300按`300×20/100`换算，假设编码器相同，不代表已完成实测。本固件只在编码器一相RISING时计数；填写左右各自实测值，**不能用旧例程462或商家四倍频计数代替**。无编码器电机不适用。
4. 确认电机线序（资料中PIN5的VCC/GND有冲突），编码器用3.3V。当前车体 B 接左、A 接右，由 `wheelChannels={1,0}` 同时映射电机和编码器；架空、低速验证`motorSign`和`encoderSign`，两轮前进反馈为正，左转角速度为正。之后才启用电机、整定前馈/PI及最大轮速。默认PI数值不是已完成的电机标定。
5. 用万用表校验INA219回传电压，验证欠压阈值及板卡版本。默认3S总压连续低于10.5V达1s锁存停车；总压不替代逐节保护。欠压或编码器故障排除后重启车端，再直接操作。电压传感器读取失败或读数超出7–16V时仅报告`warning=battery_sensor`，不停车、不锁定、不影响运动；下一次有效读数自动清除警告，异常期间电压为`null`，欠压计时清零，恢复后重新计时。

```sh
cd esp32_software/firmware
pio run                    # car-01
pio run -t upload
pio run -e car-02           # 其余car-03/car-04同理
pio run -e car-02 -t upload
pio device monitor
```

四车必须选各自环境烧录，不能四块板都用car-01身份。未创建secrets.h时使用占位网络值，仍可编译。

CAR-01 编码器断线排查可使用专用构建 `pio run -e encoder-diagnostic -t upload`（仓库根目录执行时加 `-d esp32_software/firmware`）。`0.2.5-encoder-diagnostic` 关闭编码器无响应和方向保护，使用完整 0–255 的开环 PWM；用于架空排查，PWM 不代表实际 m/s。配套 `/encoder` 页面直接调节 PWM，运行中点击「应用输出」生效，0 只停转且保持解锁。主控每 25 ms 续发，失焦或切后台继续运行，单次最多 2 分钟；退出页面或控制连接断开时停止。诊断指令到达即执行，无需校时，运动遥测回显窗口为 1500 ms，绑定/解锁仍为 200 ms。页面显示的 `motion_echo_rejections` 为回显检查拒收的开机累计次数。

旧 `0.2.3-encoder-diagnostic` 内部仍限幅 35/255，须重新烧录才能开放完整 PWM 与新回显窗口。两版均通过 `v=PWM/350` 映射；更改映射须同步更新固件版本与主控识别。诊断构建对所有控制入口生效。结束后使用 `pio run -e general-driver -t upload` 恢复普通固件。详情见[编码器线材排查](../../docs/guide/troubleshooting.md#编码器线材排查)。

从仓库根目录烧录普通固件（当前配置为编码器闭环）：

```sh
pio run -d esp32_software/firmware -e general-driver -t upload
pio device monitor -d esp32_software/firmware -e general-driver
```

串口或网页应显示固件 `0.2.9`，启动串口应有 `Motor control: closed_loop`。闭环需要普通构建中的 `encoderDiagnostic=false` 和 `motorClosedLoop=true` 同时成立；只修改后者不够，诊断模式会优先绕过 PI。`encoder-diagnostic` 构建始终使用开环 PWM。修改配置后必须重新编译并烧录，刷新网页不会更新板上固件；网页中的普通固件提示不代表实际控制模式。

当前普通固件以左右编码器测速分别进行前馈加 PI 调节；本轮架空调试起始值为 `feedForward=250`、`kp=60`、`ki=0`，先关闭积分，稳定后再考虑设为 20。诊断构建继续使用 `feedForward=350`，保持 PWM 传输映射。`encoderGuardsEnabled=false` 只关闭编码器异常停车，不会关闭闭环。确认每侧每圈计数、轮径和反馈方向正确后再整定 PI；反馈跳变会直接影响 PWM。需要隔离反馈时，将 `motorClosedLoop=false` 并重新烧录：此时目标轮速乘配置中的 `feedForward` 换算 PWM，任一轮超过 255 时两轮一起缩放。电机与编码器方向以 `include/config.h` 的 `motorSign` 和 `encoderSign` 为准，编码器排查页仍可查看原始计数曲线。

## 执行规则

独立100Hz运动任务检查TTL并更新电机输出，Wi-Fi/UDP在网络任务执行，I2C在独立低优先级任务采样；共享状态通过互斥保护。控制周期超100ms触发故障，约1s ESP任务看门狗作为后备。正常指令有效期100–500ms，从车端接收时起计算并包含排程等待，过期归零并取消解锁。重复包不会延长TTL。

启动、断网恢复后自动完成停车绑定；收到新的摇杆或运行指令时，主控自动完成 arm 握手，车端确认后下发最新且仍在有效期内的动作。网页无需手动解锁。正常零速drive保持解锁；stop取消解锁；停车或超时后可直接重新操作；链路恢复不会重放旧动作。故障锁存时只接受停车，排除原因后重启设备。

新会话或断网重绑须回显新鲜且晚于上次绑定的遥测；用递增遥测界限阻止历史会话报文重绑，移除了固定32个历史会话槽。绑定首包过旧会被拒绝，服务端会以最新遥测重试。

0.2.2 修复接收指令时对同一可变 JSON 缓冲区重复解析的问题：现在直接从已解析的报文读取指令，避免遥测在线但停车绑定一直无法确认。

0.2.3 取消实测轮速超过阈值时触发的 `wheel_overspeed` 故障停车，瞬时或持续的同向高轮速均不再因该阈值锁存。目标速度上限、摇杆限速和编码器无响应/反向异常保护继续生效。已锁存故障的设备需要烧录新固件并重启，网页解锁不能清除旧故障。

0.2.5 使用最近 5 个控制周期的脉冲总数/实际总时长估速，正常周期下窗口约 50 ms，减少单个脉冲造成的测速与 PI 输出跳变。测速与 PI 仍每 10 ms 更新，网页摇杆仍每 25 ms 发指令（40 Hz），不降低控制、输入或遥测频率。累计原始编码计数不滤波；诊断构建继续使用单周期原始测速。

0.2.6 将 `include/config.h` 中的 `encoderGuardsEnabled` 设为 `false`，完全关闭 `encoder_direction` 和左右轮 `encoder_no_response` 故障停车。该版本仍使用编码器反馈做 PI 调节，关闭故障停车并不能隔离错误反馈对输出的影响。

0.2.8 默认切换为开环，编码器无脉冲、反向和突跳均不改变 PWM。摇杆保持 40 Hz，运动任务与测速保持 100 Hz。反馈和轮径/计数校准、PI 整定完成后，可将 `motorClosedLoop=true` 恢复闭环；编码器故障停车还需独立设置 `encoderGuardsEnabled=true`，重新编译烧录。

目标轮速协调限幅、欠压停车和电压传感器异常警告继续生效。完整代码、触发条件和恢复方式见[故障与警告表](../../docs/guide/troubleshooting.md#fault-codes)。

已移除加速度限制：每个控制周期直接应用目标轮速，起步、减速、单轮归零及换向均不经过加速度插值。轮速超限时等比例缩放两轮，保持目标轮速比。整车零速立即停车。摇杆按车头控制：上前进，斜向通过轮速差走弧线，接近纯横向时平滑过渡为原地转向；协议角速度为逆时针正向。网页混合器使用当前轮距 0.122 m，与本固件 `trackWidth` 对应；更换底盘轮距时需同步调整 `frontend/src/control.ts` 中的默认轮距。

仅在普通固件同时设置 `motorClosedLoop=true` 和 `encoderGuardsEnabled=true` 时：无响应检测同时要求至少 1500 ms 无原始脉冲，且目标累计行程达到 6 个编码脉冲距离；收到脉冲即重置计时，测速平滑不会延长此超时。反向检测要求平滑反馈连续至少 1000 ms 与目标反向、绝对速度大于 0.05 m/s、目标与反馈乘积小于 −0.0001，且累计反向反馈行程达到 6 个脉冲距离。当前默认关闭这两项判定。

串口每秒输出网络、协议状态、目标/实测轮速、PWM、累计编码计数和电压；停车时目标与PWM归零。

遥测含左右累计原始编码计数、左右轮速、车速、电压、固件版本、状态/停机原因、有效速度限制与ack。没有可信电量估计时battery仍为null。公开板图INA219支路不包含电机总电流，本固件不提供虚假的电机电流/整包电流。

协议及主控启动方式见 [robot_server说明](../../robot_server/README.md)。两端必须一起升级：旧固件缺少action和显式状态，不能满足新服务端的解锁确认。

## 引脚与验证

电机A：PWM25/IN1=21/IN2=17，电机B：PWM26/IN1=22/IN2=23。编码器A在GPIO34上升沿读35，B在16上升沿读27。GPIO34/35没有内部上拉，确认实际板载信号偏置。INA219地址0x42，I2C SDA32/SCL33。

```sh
clang++ -std=c++11 -Wall -Wextra -Werror -I include test/protocol_test.cpp -o /tmp/robot-protocol-test
/tmp/robot-protocol-test
# 从仓库根目录建立共享环境；从robot_server目录运行：../.venv/bin/python -m pytest -q
```

服务端测试会编译`test/device_peer.cpp`，用真实服务端报文调用固件的`command_wire.h`和`protocol.h`，覆盖丢首包、绑定、解锁、超时和重连。需先执行过`pio run`安装ArduinoJson，并有clang++/g++。

服务端测试也会编译执行`protocol_test.cpp`、`motion_test.cpp`、`scheduler_test.cpp`、`time_sync_test.cpp`、`encoder_feedback_test.cpp`与真实电机实现的主机测试，覆盖双轮合成、排程期限、队列清空、回绕、校时、测速平滑、编码器容错与正式/诊断构建差异。

实车依次验证：架空正反方向/计数、落地低速整定、松手/断网/遮标签/关闭主控停车、欠压、重启保持停车。恢复编码器保护后，再验证编码器断线停车。软件保护不替代实体断电开关。电机方向、满充供电瞬态、温升与真实停止时间仍需实物测试。

## 时间同步与延迟缓冲

车端每秒与 server 四时间戳同步，以单调时钟映射统一 UTC。支持 `execute_at_ms` 定时运动指令，停车不等待缓冲；周期遥测为25ms。需同步更新 server 与前端，完整时序、NTP离线回退及验证说明见 [TIMING.md](../../robot_server/TIMING.md)。10ms控制周期需要重新做低速实车验证。

0.2.8 将逻辑左右轮同时映射到 B/A 电机和编码器通道，修复当前车体左右转向相反；前后方向符号保持当前配置。正角速度仍为左转（右轮目标较快）。配套主控心跳与重连阈值统一为 3 s，修复约 1.058 s 遥测空档触发重绑定；车端命令 TTL 和 40 Hz 摇杆发送频率不变。
