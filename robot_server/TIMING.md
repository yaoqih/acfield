# 控制时序与统一时间

server 为唯一时间基准，启动时映射本机 UTC 和单调时钟。后台每 300 秒尝试 NTP，失败不影响启动或控制。`ROBOT_NTP_SERVER` 默认 `pool.ntp.org`，可指定内网地址，空字符串禁用。不修改操作系统时间；校准最多以 1ms/s 渐进调整，电脑初始日期偏差较大时不会立即获得准确 UTC。TTL 和失联检测始终使用单调时钟。启动时无法获取 NTP 就使用本机时间；成功同步后断网则继续保持已建立的映射。离线时各端时间一致不代表电脑日期准确。`GET /api/time` 提供来源、最近成功时间和待校正量。事件记录与页面快照使用同一映射。

浏览器通过 WebSocket、ESP32 通过 UDP 每秒进行四时间戳同步，优选低 RTT 样本，两端均渐进校正偏移。车端基于 esp_timer 维护映射；同步超过 15 秒或估计误差超过 20ms 时不接受定时运动。网页在真实设备模式下等待两端同步完成才允许运动。误差估计依赖路径对称与晶振漂移假设，不是精度保证。WebSocket 的发送时间戳在获得发送锁后采样，排除等待快照发送的时间。固件探测与遥测时间戳以整数毫秒传输，避免 ArduinoJson 浮点序列化有效位数不足。

网页按单调时钟的 25ms 期限发送最新摇杆目标，错过周期时跳过补发，单一有序 WebSocket 避免 HTTP 等待与乱序。页面已同步时以采样时刻 +100ms 为执行时间，吸收网络抖动；其他客户端未指定时间且车端已同步时，server 默认预留 60ms。车端固定容量排程，转换成单调期限；10ms 控制任务执行，超过期限 20ms 的包丢弃，缓冲满丢弃新包，序号拒绝历史包。TTL 从车端接收时起计算，包含排程等待；保留原始 TTL 字段校验，应用时单独传入已等待时长，避免合法 TTL=100ms 等待后被误判无效。重复包不续期。零速指令清空未来运动，停车按钮取消解锁；故障和失联处理不等待排程。API 对旧客户端/未同步设备仍支持即时指令，该降级路径不保证固定延迟。

周期遥测和页面快照均为 25ms，车端接受指令后尽快遥测。`ack_seq` 表示协议接受，`applied_seq` 表示控制更新已处理，均不代表机械动作发生。`sampled_at_ms` 是遥测构建时间，轮速来自最近控制周期。快照含同步状态与误差估计。串口打印移至锁外；I2C 采样移至独立低优先级任务。

“最近更新”只计算本页面距上次收到服务器快照的单调时钟间隔，界面标为“服务器推送”。该数字不是小车遥测年龄、单向网络延迟或端到端动作延迟。不会用 Unix 时间减 performance.now()，也不会因系统日期或校时变化跳变。

控制通道拥塞或断开时，网页通过 HTTP 备用路径停车并锁定，阻止排队中的旧 WebSocket 运动消息恢复行驶；恢复后需重新解锁。

## 摇杆与双轮合成

以车头为基准：上为前进，右为原地右转；倒车时推右仍产生顺时针角速度。网页采用连续径向死区，离开死区时速度从零连续增加；斜向按同一向量归一化，不分别裁切两个轴。车端遵循 `left=v-omega*track/2`、`right=v+omega*track/2`，角速度正向为逆时针。

轮速超限时等比例缩放两轮；加速度限制也共用一个插值比例。原先每轮各自以相同步长加速，斜向起步会暂时出现左右轮等速，曲率错误；单轮原始目标归零时的立即清零也会使切换不连续。现在从静止起步保持目标轮速比，切换时两轮一起到达新目标，经过零速或反向也受同一加速度约束。整车零速及紧急停车仍立即切断输出。PI 参数与加速度数值未调节。

## 延迟目标与验收边界

正常网络预算内，排程目标为摇杆目标采样到 PWM 更新约 100–110ms，另加校时和任务调度误差；用户输入到下一次目标采样最多还需一个 25ms 周期。这个区间是设计预算，未经实车测量，不能当作保证值。拥塞超过预算时丢包并最终 TTL 停车，不无限增加延迟。周期反馈仍有等待时间，返回时间不是恒定值；机械响应还受目标幅度、轮速加速度、静摩擦和负载影响。模拟模式立即应用目标，不用于证明真实设备的排程延迟。

需同时更新 server、前端与固件。10ms 控制周期改变编码器测速量化，需要架空低速验证 PI、编码器诊断、拥塞及断网停车，再落地测试。验收记录 P50/P95/P99：采样→接收→PWM→首个编码脉冲→页面反馈。

自动回归覆盖真实固件头文件的方向/曲率/换向/轮速限幅、短 TTL 排程/迟到/重复/乱序/队列满/停车/时钟回绕，以及页面拖动/键盘组合/松手/锁定与时间显示。运行服务端 `pytest` 会编译执行固件主机测试；前端构建后，在仓库根目录运行 `npm run console:test` 验证页面。
